AI 面试训练平台

面向计算机方向求职者的一站式系统：AI 按方向与难度出题并评分追问、AI 优化简历、AI 基于简历模拟 HR 面试，全程以可观测的 Agent 执行链路运行，产出训练报告与能力画像。

1文档说明

1.1 目的

本文档定义「AI 面试训练平台」用户端的产品范围、功能需求、AI 能力设计、RAG 与向量数据库落点、技术架构、数据模型、交付路线与验收标准，作为立项评审、UI 设计、前后端开发与 AI 工程实现的统一依据。

1.2 读者

  • 产品 / 设计：依据第 2–4、11–12 章确定范围、原型与验收口径。
  • 后端 / 前端：依据第 6、8、9 章实现业务、流式交互与可观测面板。
  • AI 工程师：依据第 6、7 章实现 Agent 编排、RAG、评分与记忆。

1.3 非目标（一期不做）

  • 管理员端、题库运营后台、企业端、付费订阅与支付。
  • 非计算机专业（法律/医学等）的题库与评分模板。
  • 多模态面试（语音/视频）、代码沙箱判题（P1 可选）。

1.4 术语

术语含义
Agent由 LLM 驱动、可调用工具并维护状态的自主执行单元。
ReAct「思考—行动—观察」循环，Agent 在工具调用与模型推理间迭代直至产出最终结果。
RAG检索增强生成：先从知识库检索相关片段，再注入上下文让 LLM 生成。
Embedding / Rerank将文本转为向量 / 对初召回结果做精排。
可观测用户可实时看到 Agent 的模型、工具、记忆、向量检索等调用过程。
能力画像用户长期学习形成的结构化掌握度评估（知识点 × 维度）。

2产品总览

产品由四条闭环构成，共享同一套用户画像、RAG 知识库与可观测 Agent 运行时：

闭环一 · 定向刷题

按专业 / 技术方向 / 难度出八股、算法、业务题，AI 出题并去重。

闭环二 · 作答评测

作答后 AI 多维评分、给参考答案、按上下文追问，支持收藏错题。

闭环三 · 简历优化

上传 PDF 简历 + 企业 JD，AI 分析匹配度并给出可落地的优化建议。

闭环四 · 模拟面试

AI 针对简历中的项目 / 技术栈深挖提问并追问，实时评分并出面试报告。

贯穿性能力

以上四条闭环共用：长期能力画像（决定出题与追问策略）、可观测 Agent 执行面板（产品差异化卖点）、训练报告与能力雷达（闭环一的出口）。

3核心用户流程

3.1 刷题训练流程

  1. 选择条件：专业（计算机）、技术方向（后端 / 前端 / 算法 / 测试 / 网络 / OS / 数据库）、难度（入门 / 初级 / 中级 / 高级）、题型（八股 / 算法 / 业务）。
  2. AI 出题：综合用户薄弱点与选题条件，生成题目（算法题附带输入输出样例与约束）。
  3. 作答：文本 / 代码块作答并提交。
  4. AI 评测：多维评分 + 维度理由 + 参考答案 + 改进建议。
  5. 追问：AI 基于上一问与作答进行 1–3 轮追问，逐轮评分。
  6. 沉淀：错题自动入库、答案存档、更新能力画像；可一键生成单次训练报告。

3.2 简历优化流程

  1. 上传 PDF 简历，系统解析为结构化文本（含表格、项目、技能、经历分段）。
  2. （可选）粘贴或上传目标企业 JD。
  3. AI 分析：亮点、短板、与 JD 的技能匹配度、缺失技能清单。
  4. AI 建议：结构、措辞、量化结果、关键词、项目描述的分点优化建议，支持逐条改写套用。
  5. 输出匹配度评分与可导出的优化后简历草稿。

3.3 模拟面试流程

  1. 选择面试岗位方向、难度、时长（如 15 / 30 分钟）、是否压力面试。
  2. AI 开场并自我介绍环节，随后进入项目深挖或技术栈提问。
  3. 每轮：AI 提问 → 用户作答 → AI 实时评分 + 简短反馈 → AI 追问。
  4. 每问附带参考答案与考察点（用户可在结束后查看）。
  5. 面试结束输出：总分、逐轮评价、改进建议、能力雷达对比。

4功能需求

4.1 刷题模块（FR-A）

编号需求说明 / 验收要点
A1出题条件专业、技术方向、难度、题型四维组合；可单选或随机组合。
A2AI 出题LLM 生成题目；算法题需含输入输出样例、约束、测试点；八股/业务题需含考察点标签。
A3题目去重新题与题库向量相似度超阈值时复用已有题，避免重复出题。
A4题源混合种子题库（结构化）+ RAG 检索相似题 + LLM 生成三者混合，保证质量与多样性。

4.2 作答评测与追问（FR-B）

编号需求说明 / 验收要点
B1作答输入支持富文本与代码块；算法题支持语言标记的代码输入。
B2多维评分正确性 / 完整性 / 表达 / 术语各 0–5 分，加权总分 + 每维理由（见 6.4）。
B3参考答案每题给出 AI 参考答案与考点解析，用于对照学习。
B4上下文追问基于上一问与作答生成追问，1–3 轮，逐轮评分，形成追问链。
B5可解释性评分必须输出维度理由，禁止仅返回裸分数。

4.3 收藏 / 错题 / 训练报告（FR-C）

编号需求说明 / 验收要点
C1收藏收藏题目并可打标签、查看。
C2错题本评分低于阈值的题目自动归入错题，支持复习与重做，重做正确后移除。
C3回答存档所有答案、评分、追问链可回溯查看。
C4训练报告单次训练报告：题目清单、得分、追问链、薄弱点、改进建议。
C5能力分析长期画像：知识点掌握度、各维度得分趋势（见 6.3）。
C6雷达图多维能力雷达（方向 × 维度），支持与历史对比。

4.4 简历优化（FR-D）

编号需求说明 / 验收要点
D1PDF 解析上传 PDF，解析为结构化文本；扫描件走 OCR 兜底。
D2JD 输入粘贴或上传 JD 文本，解析岗位画像（职责、必备技能、加分项）。
D3匹配分析输出简历与 JD 匹配度、亮点、短板、缺失技能清单。
D4优化建议分点建议（结构 / 措辞 / 量化 / 关键词 / 项目描述），支持逐条改写并套用。
D5简历草稿生成优化后简历草稿，可导出。

4.5 模拟面试（FR-E）

编号需求说明 / 验收要点
E1面试配置基于简历 + 目标岗位选择方向、难度、时长。
E2HR 提问针对简历中某个项目或技术栈深挖提问（STAR 法），持续追问。
E3实时评分每轮作答后实时评分 + 简短反馈。
E4参考答案每问附参考答案与考察点。
E5面试报告最终评价、总分、逐轮表现、改进建议、能力雷达。
E6追问策略支持项目深挖、技术栈深挖、压力测试三种追问风格。

4.6 Agent 可观测（FR-F，横切）

编号需求说明 / 验收要点
F1执行面板实时展示：模型调用（模型名 / token / 延迟）、工具调用（名 / 参数摘要 / 结果摘要）、记忆读写、向量检索（query / 命中 top-k）。
F2不暴露思维链默认不展示原始 CoT；如需展示须脱敏为高层动作摘要。
F3可回溯完整 trace 存档，可回看任意历史会话的执行过程。
F4中断支持随时中断 Agent 执行，保留已产生的中间状态。

4.7 账户与数据（FR-G，横切）

编号需求说明 / 验收要点
G1认证邮箱 / 手机注册登录，JWT 会话。
G2数据隔离简历、报告、画像、会话仅本人可见，多租户隔离。
G3用量配额token 用量、每日出题 / 面试次数配额，超限提示。
G4内容安全输入输出安全审查，过滤违规与越权内容。

6AI Agent 设计

6.1 编排模型

采用 LangGraph 状态图 建模：节点 = 模型调用 / 工具调用，边 = 条件路由。核心价值：

  • 流式事件：每个节点执行即产生结构化事件，直接映射到前端「执行面板」（见 4.6）。
  • Checkpoint：状态可持久化与恢复，天然支撑「记忆」与「中断后恢复」。
  • 循环可控：ReAct 循环的终止条件、最大步数、工具白名单显式可控，避免失控。
为什么自控 loop 而非黑盒框架

「用户实时看到工具 / 记忆 / 向量检索调用」是本产品卖点。LangGraph 暴露每一步事件，让我们精确埋点；纯黑盒 Agent 反而拿不到这些信号。因此编排层用 LangGraph 显式建图，而不是依赖不可见的内部循环。

6.2 工具集（Tool Registry）

工具输入输出用途
generate_question方向 / 难度 / 题型 / 薄弱点题目 + 样例 + 考点出题
grade_answer题目 + 作答 + 参考答案多维评分 JSON评分
generate_followup上一问 + 作答 + 画像追问 + 参考答案追问
retrieve_knowledgequery + 过滤条件top-k 片段 + 分数RAG 检索
parse_resumefile_id结构化简历 JSON简历解析
parse_jdJD 文本岗位画像 JSONJD 解析
save_memory类型 + 内容确认写长期记忆
read_memory类型 + 过滤画像片段读长期记忆

6.3 记忆系统（三层）

层载体内容生命周期
短期记忆Redis + 会话状态当前会话滚动上下文、摘要压缩后的历史会话级
长期记忆PostgreSQL + 向量能力画像：知识点掌握度、薄弱点、历史表现、简历画像用户级，持续更新
知识记忆向量数据库题库、面经、参考答案等 RAG 语料全局，可运营更新

6.4 评分量表（可解释评分）

维度分值权重考察点
正确性0–50.40结论是否正确、有无硬伤
完整性 / 深度0–50.30是否覆盖要点、能否深入机制
表达与结构0–50.15逻辑是否清晰、结构化表达
术语准确性0–50.15专业术语使用是否准确

评分以 结构化输出（JSON Schema） 强制约束：{score, dimensions:{correctness:{score,reason},...}, strengths, suggestions, reference_answer}。加权总分 = Σ(维度分 × 权重)。

6.5 提示词策略

  • 系统提示词分层：角色设定 + 领域规则（评分量表、追问策略）+ 工具使用说明，模块化拼接。
  • Few-shot：每类题型提供 1–2 个「高质量题目 + 参考答案 + 评分」范例，稳定输出格式。
  • 结构化输出：评分、简历解析、JD 解析均用 JSON Schema 约束，降低解析错误。
  • 画像注入：出题与追问时把长期画像（薄弱点）注入上下文，实现个性化。

7RAG 与向量数据库

7.1 三个知识库

知识库内容服务于隔离性
题库知识库八股 / 算法 / 业务题 + 参考答案 + 考点出题、评分参照、给答案全局共享
面经 / 企业库面经、企业面试风格、岗位高频题模拟面试真实性全局共享
用户简历库用户简历 + JD 结构化片段简历诊断、模拟面试提问按用户隔离

7.2 数据流

  1. 入库：文档 / 题目 → 结构化分块 → BGE-M3 Embedding → 写入向量库（带元数据：方向、难度、题型、用户 ID）。
  2. 检索：query → Embedding → 向量库 top-k 召回（含元数据过滤）→ bge-reranker-v2-m3 重排 → 取 top-n 片段。
  3. 拼接：检索片段 + 用户画像 + 系统提示词 → 注入 LLM 上下文。

7.3 选型

组件选型说明
向量数据库Qdrant（MVP）→ Milvus（规模化）标量 + 向量混合过滤，匹配「方向 / 难度 + 语义」双条件
EmbeddingBGE-M3（本地）中英双语、8192 上下文、dense + sparse 双路
Rerankbge-reranker-v2-m3召回后精排，提升 top-k 命中质量
检索框架LlamaIndex分块、索引、query engine 组件化，与 LangGraph 组合

7.4 分块策略

  • 题目：按「题干 / 参考答案 / 考点」结构化分块，元数据过滤优先于纯语义召回，保证检索准确。
  • 简历：按「项目经历 / 技能 / 教育 / 工作经历」分块，便于模拟面试针对单一项目深挖。
  • 面经：按「问题 / 公司 / 岗位方向」分块。
向量库的边界

向量数据库只承载语义检索，不替代事务数据。用户答案、评分、会话、画像、报告等强一致、需关联查询的数据一律存 PostgreSQL；向量库仅存可检索的文本片段及其元数据，两者以 chunk_id 关联。

8.3 服务边界

  • 模块化单体起步：MVP 用单进程 FastAPI 按领域分包（账户 / 题库 / 训练 / 简历 / 面试 / 报告），避免过早拆微服务。
  • AI 编排为核心模块：LangGraph 图与工具注册表独立成包，后续可平滑拆为独立 AI 服务。
  • 异步边界：简历解析、报告生成等长任务走 ARQ 队列，不阻塞请求线程。

8.4 流式与可观测

  • 服务端将每个 Agent 步骤封装为结构化 step event（类型、载荷、耗时），经 SSE 推给前端。
  • 前端「执行面板」按事件类型渲染对应组件（模型卡片 / 工具卡片 / 检索结果 / 记忆写入）。
  • 完整 trace 同步写 Langfuse，供回溯与成本分析（见 5 章）。

10安全与合规

  • 认证授权：JWT + RBAC；用户仅能访问自己的简历、报告、画像与会话（FR-G2）。
  • 数据加密：简历与报告字段静态加密；传输 TLS；日志脱敏（姓名、联系方式、邮箱）。
  • 向量库隔离：用户简历库以 user_id 作为过滤元数据，检索强制携带该过滤，杜绝跨租户泄露。
  • 内容安全：输入输出安全审查（越权、违规内容、提示注入），LLM 输出不直接执行代码。
  • 隐私合规：采集告知、删除权、数据导出；简历为个人信息，需最小化存储与可删除。
  • 成本防护：每日配额、限流、超时熔断，防止 token 滥用。
