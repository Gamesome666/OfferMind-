## 1. 术语表

> 按「偏科普」的阅读要求，每条给一句通俗解释。首次出现在正文中的术语都可在本表查到。

### 1.1 AI 与检索

| 术语 | 一句话解释 |
|---|---|
| **LLM**（大语言模型） | 能理解和生成自然语言的神经网络模型，本项目用云端 DeepSeek 与本地 Qwen |
| **RAG**（检索增强生成） | 让模型先「查资料」再回答，而不是凭记忆答。查到的资料拼进 prompt 当参照 |
| **Agentic RAG** | 不是「查一次答一次」，而是由 Agent 自主决定什么时候查、查什么、要不要重试 |
| **Agent**（智能体） | 能自主执行多步决策的程序，本项目由 LangGraph 编排 |
| **ReAct** | 「推理 + 行动」交替的 Agent 范式：模型思考 → 调用工具 → 看结果 → 再思考 |
| **工具调用**（function calling / tool calling） | 让模型输出「我要调哪个函数、参数是什么」，由程序执行后把结果返回给模型 |
| **Embedding**（嵌入） | 把一段文本映射成一个高维向量（本项目 1024 维），语义相近的文本向量也相近 |
| **稠密检索** | 用 Embedding 向量做相似度搜索。强在理解语义，弱在对精确词（`LRU`、`CAS`）不敏感 |
| **稀疏检索** | 基于词频的传统检索。强在字面精确匹配，弱在语义泛化 |
| **BM25** | 最经典的稀疏检索算法，按词频与逆文档频率给文档打分 |
| **Rerank**（精排） | 召回一批候选后，用一个更精确但也更慢的模型重新排序。常见做法是「召回 2 倍、精排保留 1 倍」 |
| **交叉编码器** | 把「查询 + 文档」一起送进模型打分（对比「双塔」分别编码再算相似度），更准但更慢 |
| **RRF**（倒数排名融合） | 把两路检索结果按**名次**融合，不按分数 —— 因为两路分数量纲不同、不可比 |
| **HyDE** | 先让模型生成一段「假想答案」，用假想答案的向量去检索 —— 对短查询效果通常更好 |
| **向量库** | 专门存储与检索向量的数据库，本项目用 Qdrant |
| **Top-k** | 取相似度最高的前 k 条 |
| **Chunk**（分块） | 把长文档切成小片段再入库。本项目一题一个 point，未分块 |
| **幻觉** | 模型编造出看似合理但实际错误的内容 |

### 1.2 编排与工程

| 术语 | 一句话解释 |
|---|---|
| **LangGraph** | 把 Agent 流程表达成「状态图」的框架：节点 + 边 + 共享 state |
| **StateGraph** | LangGraph 的核心类，用节点与边构建有向图 |
| **State**（状态） | 图中所有节点共享读写的数据对象，本项目有 34 个字段 |
| **Node**（节点） | 图中的一个执行步骤，读写 state |
| **条件边** | 根据 state 决定下一步走哪个节点，可实现循环与分支 |
| **reducer** | 多个节点写同一字段时的合并规则。本项目 `traces` 用 `operator.add` 累加，其余字段覆盖 |
| **checkpointer** | LangGraph 的状态持久化机制，支持中断续跑。**本项目未使用** |
| **stream writer** | 让节点在执行过程中主动向 SSE 流推事件的机制 |
| **SSE**（Server-Sent Events） | 服务器向浏览器单向持续推送文本的协议。本项目所有 Agent 执行都走 SSE |
| **step event** | 本项目定义的步骤事件：`{id, type, status, payload, duration_ms}` 五字段 |
| **LangChain** | LLM 应用开发框架，本项目借用了它的消息类型与少量工具 |
| **LCEL** | LangChain 表达式语言，用 `|` 组合链式调用 |
| **LlamaIndex** | 另一个 RAG 框架，本项目未使用 |
| **LiteLLM** | 统一的 LLM 调用库，支持多服务商与多部署路由。本项目用作网关 |
| **Fallback**（回退） | 主模型失败时自动切到备选模型 |
| **Pydantic** | Python 数据校验库，本项目用它定义结构化输出 schema |
| **ORM** | 对象关系映射，把数据库表映射成 Python 类。本项目用 SQLAlchemy |
| **中间件** | 在请求处理的管道中插入的统一处理层，如 CORS |
| **CORS** | 跨域资源共享，浏览器限制前端访问不同源的后端 |
| **JWT** | JSON Web Token，一种无状态的身份凭证 |
| **bcrypt** | 一种密码哈希算法，故意设计得慢以抵抗暴力破解 |
| **多租户隔离** | 多个用户共用系统但互相看不到对方数据 |

### 1.3 微调与部署

| 术语 | 一句话解释 |
|---|---|
| **微调**（fine-tuning） | 在预训练模型基础上用特定任务数据继续训练，让它更适合这个任务 |
| **SFT**（监督微调） | 用「输入 → 期望输出」的成对样本做微调 |
| **LoRA** | 只训练一小部分「低秩适配器」参数的高效微调方法，显存开销远小于全参微调 |
| **LoRA rank**（r） | 适配器的秩，越大容量越强也越容易过拟合。本项目 r=16 |
| **数据飞轮** | 产品运行产生的数据反过来用于训练模型、提升产品，形成正循环 |
| **LLaMA-Factory** | 配置化的微调框架，一个 YAML 完成训练 |
| **alpaca 格式** | 一种常见的 SFT 数据格式：`{instruction, input, output, system}` |
| **训推一致** | 训练时与推理时的输入格式必须一致，否则模型学的和用的不是一回事 |
| **vLLM** | 高吞吐 LLM 推理引擎 |
| **PagedAttention** | vLLM 的核心技术，像操作系统管理内存那样按页管理 KV cache，减少显存碎片 |
| **前缀缓存**（prefix caching） | 缓存多请求间重复的 prompt 前缀（如 system prompt），避免重复计算 |
| **连续批处理**（continuous batching） | 不等整批请求都完成就动态补入新请求，大幅提升吞吐 |
| **量化**（quantization） | 用更低精度表示模型权重以省显存。FP16 是半精度基线，AWQ / GPTQ 是 4bit 方案 |
| **TTFT**（首 token 延迟） | 从发出请求到收到第一个 token 的时间，决定「体感快慢」 |
| **QPS** | 每秒查询数，衡量吞吐 |
| **P50 / P95 / P99** | 分位数。P99 = 99% 的请求都比这个值快，用来观察尾部延迟 |
| **MAE** | 平均绝对误差，衡量预测值与真值的平均偏离幅度 |

### 1.4 业务与算法

| 术语 | 一句话解释 |
|---|---|
| **rubric**（评分量表） | 明确的评分维度与分值定义，让主观评分变得可复现 |
| **四维评分** | 本项目的评分体系：正确性 0.40 / 完整性 0.30 / 表达 0.15 / 术语 0.15，各 0–5 分 |
| **SM-2** | 经典的间隔重复算法，根据回忆质量动态调整下次复习间隔 |
| **间隔重复** | 在「快要忘记」的时间点复习，用最少次数达到最牢记忆 |
| **ease**（难度系数） | SM-2 里的参数，答得越好增长越多，控制间隔增长的速度 |
| **JD**（Job Description） | 职位描述 |
| **一致率** | 本项目的评测指标：与人工评分相差 ≤1 分算一致 |
| **能力画像** | 对用户各知识点掌握度的长期记录 |

## 2. 本地环境搭建

### 2.1 前置要求

| 项 | 要求 |
|---|---|
| Python | **3.11+** |
| Node.js | 支持 Next.js 15 |
| Docker | 用于起基础设施 |
| conda 环境 | 项目使用 `langchain_latest` |

### 2.2 完整搭建步骤

```bash
# ---------- 1. 起基础设施 ----------
cd backend
docker compose up -d
docker compose ps          # 应看到 5 个容器 Up

# ---------- 2. 配置环境变量 ----------
cp .env.example .env
# 编辑 .env，至少填 DEEPSEEK_API_KEY 与 JWT_SECRET

# ---------- 3. 建表与迁移 ----------
python init_db.py          # 应打印「数据库表已创建 / 更新」

# ---------- 4. 题库入库 ----------
python -m app.rag.ingest   # 应打印「题库入库完成，共 12 道题」

# ---------- 5. 启动后端 ----------
uvicorn app.main:app --reload
# 启动后约 25 秒，日志出现两条「模型预热完成」

# ---------- 6. 建第一个管理员 ----------
python promote_admin.py <你的邮箱>

# ---------- 7. 启动前端 ----------
cd ../frontend
npm install
npm run dev                # 3000 端口
```

### 2.4 两个新手最容易踩的坑

| 坑 | 说明 |
|---|---|
| **必须用 `127.0.0.1` 而不是 `localhost`** | Windows 下 `localhost` 会优先解析到 IPv6 的 `::1`，而 Docker 只映射了 IPv4，连 `::1` 会静默超时 20 秒以上 |
| **前后端分别在不同终端启** | 后端 `uvicorn`、前端 `npm run dev`，不要混在一个终端 |

### 2.5 部署侧工具链的额外安装

以下工具**不在 `pyproject.toml` 里**，需要独立环境或额外安装：

| 用途 | 安装 |
|---|---|
| vLLM 本地服务 | `pip install vllm`（需 CUDA 环境） |
| LoRA 训练 | `pip install llamafactory` |
| LiteLLM Proxy 形态 | `pip install 'litellm[proxy]'` |

**⚠️ 强烈建议独立 conda 环境**：LLaMA-Factory 与 vLLM 会引入自己的 `transformers` / `torch` 版本约束，装进主环境可能与 BGE-M3 的 `sentence-transformers`（依赖 `transformers 4.x`）冲突。

**`backend/.env` 中包含真实的 API 密钥明文。**

**`app/agent/` 的文件职责**：

| 文件 | 职责 |
|---|---|
| `graph.py` | 9 张 LangGraph 图 + 所有节点函数 + `_start` / `_finish` 事件推送 |
| `llm.py` | `JsonSchemaLLM`（结构化输出）+ `get_llm`（客户端构造与缓存）+ `astream_chat` |
| `gateway.py` | 进程内 LiteLLM Router + `LiteLLMChat` 薄适配器 |
| `prompts.py` | 全部 prompt 模板（**微调与评测脚本复用的关键资产**） |
| `schemas.py` | 模型结构化输出的 Pydantic 模型（如 `GradeOutput`） |
| `state.py` | `AgentState`（34 个字段） |
| `tools.py` | 工具定义与 `ALL_TOOLS` 注册表（**当前未被编排消费**） |
| `interview_chat.py` | 面试对话生成器（**不是 StateGraph**） |
| `service.py` | 业务编排 + `_stream` / `_invoke` |

**`app/rag/` 的文件职责**：

| 文件 | 职责 |
|---|---|
| `embeddings.py` | BGE-M3 单例懒加载 + 双重检查锁 |
| `reranker.py` | bge-reranker-v2-m3 单例懒加载（同构写法） |
| `vectorstore.py` | Qdrant 入库/删除/检索（三模式 + 精排 + 事件推送） |
| `bm25.py` | 稀疏检索 + RRF 融合 + 单例与失效 |
| `ingest.py` | 种子题库入库脚本 |
| `seed_data.py` | 12 道种子题目（后端 6 / 前端 3 / 算法 3） |

**一个容易被忽略的副作用**：`app/rag/__init__.py` 里全局设死了离线模式：

```python
os.environ.setdefault("HF_HUB_OFFLINE", "1")
os.environ.setdefault("TRANSFORMERS_OFFLINE", "1")
```

避免冷启动时向 huggingface.co 发 HEAD 请求白等 20–30 秒。

## 6. 离线脚本速查

| 脚本 | 用途 | 常用命令 |
|---|---|---|
| `scripts/bench_llm.py` | LLM 压测（P50/P95/P99 + QPS + 首 token） | `python scripts/bench_llm.py --label cloud` |
| `scripts/eval_grader.py` | 评分器评测与前后对比 | `--make-template 100` / `--label before` / `--compare A B` |
| `scripts/export_sft_dataset.py` | 导出 SFT 数据集（alpaca） | `--stats-only` / `--drop-degenerate` |

**三个脚本的共同约定**：`--base-url` / `--model` / `--api-key` 缺省时**从数据库读运行时配置**，而不是读 `.env`（因为管理员可能改过配置，`.env` 已过期）。
